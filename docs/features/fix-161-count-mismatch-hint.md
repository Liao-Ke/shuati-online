# 修复：筛选后实际题数少于设定值时明确提示（issue #161）

**日期：** 2026-07-27  &emsp; **关联 Issue：** #161

## 问题

题目数量滑杆上限只按所选题库**全部题数**计算，不感知题型/章节筛选；后端
`start_exam` 先按筛选过滤候选，`question_count >= 候选数` 时静默取全部候选。
100 题题库筛出 20 道选择题、滑杆设 50，实际开考 20 题，全程无提示。

## 修复口径选择

Issue 期望给出两个可接受口径：上限随筛选实时联动，或实际题数少于设定值时
提示。前者需要按题型/章节的计数数据（新增统计接口，或前端全量拉取题目——
与 #149 刚消除的开销同类），属功能扩展；本修复取后者（最小闭环）：

`startExam` 成功响应后，`res.total_count < 设定值` 时 alert
「筛选后符合条件的题目只有 X 道，少于设定的 Y 道，将按实际题数作答」，
随后正常进入考试。代码处已留 ponytail 注释标注联动方案的升级路径。

## 验证方式

```bash
node --test tests/frontend/*.test.js   # 39 pass（新增 2 项）
```

新增 `tests/frontend/count_mismatch_hint.test.js`：设定 50 实际 20 → 提示含
两个数字且仍进入考试；设定与实际相等 → 不打扰。已红-绿验证：旧代码下
提示用例失败。

## 已知限制

- 提示发生在开考成功后（数据此时才可知），设置页滑杆上限仍显示题库总题数；
  实时联动为独立功能（需新增统计接口），见代码 ponytail 注释。
