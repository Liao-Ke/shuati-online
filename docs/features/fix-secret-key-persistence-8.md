# 修复 SECRET_KEY 重启后 JWT 失效（#8）

**日期：** 见文件修改时间  &emsp; **关联 Issue：** #8

## 目标

`auth.py` 在未设置 `SECRET_KEY` 环境变量时，每次启动通过 `secrets.token_hex(32)` 生成新随机密钥，导致重启后所有已签发 JWT 失效。本次修复将生成的密钥持久化到本地文件 `.secret_key`，下次启动时复用，确保开发环境下重启不影响已登录用户。

## 修改范围

- `auth.py`：替换密钥加载逻辑
- `.gitignore`：追加 `.secret_key`
- `test_auth.py`：新增 4 个单元测试

## 核心实现

1. 新增 `_load_secret_key(path=None)` 函数，优先级：
   - 环境变量 `SECRET_KEY`（最高优先级，生产环境必走此路径）
   - `.secret_key` 文件（开发环境持久化密钥）
   - 生成新密钥并写入文件（首次启动）
2. 文件读写异常做兜底：读取失败时生成新密钥，写入失败时仅 warning 不阻断启动
3. 生成密钥时打印 WARNING 日志，提示生产环境应通过环境变量设置

## 影响范围

- 仅影响未设置 `SECRET_KEY` 环境变量时的密钥加载行为
- Docker 部署不受影响（`docker-compose.yml` 中已有 `${SECRET_KEY:?...}` 强制校验）
- 已设置环境变量的部署行为不变

## 验证方式

1. `pytest test_auth.py -v` — 4 个单元测试通过（环境变量优先、文件读取、生成持久化、跨重启一致性）
2. `pytest test_integration.py -v` — 66 个集成测试全部通过（回归确认）

## 已知限制

- `.secret_key` 文件权限未做特殊限制（默认 644），开发环境可接受。生产环境应通过环境变量设置密钥，不依赖文件持久化。
- 文件写入失败时（如只读文件系统），密钥仅在本次进程有效，重启后 JWT 仍会失效。此场景下日志 WARNING 会明确提示。
